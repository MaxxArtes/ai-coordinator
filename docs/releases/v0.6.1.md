# AI Coordinator v0.6.1 — Notas de Lançamento (Patch de Segurança e Confiabilidade)

**Data de Publicação:** 2026-11-27  
**Versão:** `0.6.1`  
**Status:** Release estável publicada (patch prioritário de segurança e confiabilidade)  
**Advisory de Segurança:** `GHSA-j9xw-7pjv-hrgh`

---

## 1. Resumo das Correções

A versão **v0.6.1** do `ai-coordinator` corrige uma falha de contenção na mailbox do Tool Broker no Windows (`GHSA-j9xw-7pjv-hrgh`), endurece a validação *fail-closed* de identidade de diretórios no launcher e corrige falhas de failover pós-spawn e contagem de tentativas de workers.

### 1.1. Segurança — Fixação Fail-Closed da Mailbox no Windows (`ToolBroker`)
- **Exigência explícita de handle fixado no Windows:** `ToolBroker.process_mailbox()` verifica via `_require_pinned_nt` que todos os diretórios da hierarquia (raiz da sandbox, `.broker`, `.broker/requests`, `.broker/responses`) possuem handles abertos sem `FILE_SHARE_DELETE`. Se qualquer diretório desaparecer ou for substituído entre a checagem inicial e `pin()`, o ciclo falha fechado (`ReparseEscapeError` quando `raise_on_fatal=True`, ou `SymlinkSecurityViolation` caso contrário).
- **Protótipos `ctypes` para `kernel32`:** Declarados `argtypes` e `restype` (`wintypes.HANDLE`, `wintypes.DWORD`, `wintypes.BOOL`) para `CreateFileW`, `GetFileAttributesW`, `GetFinalPathNameByHandleW` e `CloseHandle`, corrigindo em Python 64 bits no Windows a detecção de `INVALID_HANDLE_VALUE` (`2^64 - 1`).
- **Verificação estrita do caminho final do handle:** `_PinnedDirectory.pin()` fecha o handle e falha fechado se `GetFinalPathNameByHandleW` falhar ou retornar caminho fora da sandbox.
- *Observação:* Ambientes Linux e macOS não são afetados por esses dois caminhos, pois operam por descida estritamente relativa via `dir_fd` com `O_DIRECTORY | O_NOFOLLOW`.

### 1.2. Segurança — Identidade de Diretório Fail-Closed no Launcher (`cli.launch`)
- Substituída a comparação direta por `Path.samefile` pelo helper `_verified_same_directory(a, b)` usando `os.stat`.
- Exige `stat.S_ISDIR`, `st_ino != 0` e `st_dev != 0` em ambos os caminhos; em caso de `0`, não-diretório ou `OSError`, recusa *fail-closed* com `ValueError` explícito (sem fallback para comparação de strings).

### 1.3. Confiabilidade — Failover Pós-Spawn e Contrato de Worker
- **Failover consistente no mesmo `run_id`:** `run_worker` e `Store.begin_worker_attempt` rearmam o estado para `starting` após falhas pós-spawn depois de limpar `pid` e `process_create_time`, evitando o erro `Transicao de estado invalida: running -> starting`.
- **Filtro antecipado por contrato (`B3-07`):** `run_worker` e `runtime.route_plan` verificam `get_client_contract(candidate["client"], "worker") is None` antes de incrementar `attempts`, chamar `begin_worker_attempt` ou consumir `attempts_per_run`, registrando o candidato em `skipped` com `state: "contract_unsupported"`.

## 2. Matriz de Versões Afetadas e Orientações de Atualização

| Componente / Versão | Sistema Operacional | Situação | Ação Recomendada |
|---|---|---|---|
| Core `v0.1.0` a `v0.4.0` | Todos | **Não afetadas** (`tool_broker.py` inexistente) | Atualizar para `v0.6.1` se desejar recursos atuais |
| Core `v0.5.0` | Windows | **Afetada** (`tool_broker.py` sem pinagem por handle) | **Atualizar para `v0.6.1`** |
| Core `v0.5.1` a `v0.6.0` | Windows | **Afetada** (`GHSA-j9xw-7pjv-hrgh`) | **Atualizar imediatamente para `v0.6.1`** |
| Desktop `v0.6.1-alpha.49`, `.50`, `.52` | Windows | **Afetadas** (embarcam Core `v0.6.0`) | **Atualizar para `v0.6.1-alpha.53`+** |
| Core / Desktop | Linux e macOS | **Não afetados** pela vulnerabilidade investigada | Atualizar normalmente |
| **Core `v0.6.1`** | Todos | **Corrigida** | Versão recomendada (GitHub Release + PyPI) |
| **Desktop `v0.6.1-alpha.53`** | Windows x64 | **Corrigida** (embarca Core `v0.6.1`) | Pre-release recomendada para usuários alpha |

### Como atualizar
```bash
pip install --upgrade "ai-coordinator>=0.6.1"
```
Para ambientes com servidor MCP opcional:
```bash
pip install --upgrade "ai-coordinator[mcp]>=0.6.1"
```

## 3. Compatibilidade e Migração

- **Compatibilidade bidirecional `v0.6.0` <-> `v0.6.1`:** Schema SQLite preservado integralmente; bancos de `v0.6.0` são lidos e gravados sem perda de dados por ambas as versões.
- **Migração `v0.4.0` -> `v0.6.1`:** Verificada via `scripts/verify_clean_install_and_migration.py` em ambiente virtual isolado, incluindo dependência opcional `[mcp]`.
